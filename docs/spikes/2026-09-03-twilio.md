# Spike 0b — Twilio: `lines add twilio` end to end on a trial account (2026-09-03)

**Question.** Does the Twilio flow written from the docs — credential list, SIP domain with registration, number, TwiML,
Elastic SIP trunk — work against the real API on a fresh trial account, register from behind a home router, take a call
and place one? **Answer: yes, first time, in one command**, and it also closed the provisioning gap the Telnyx account's
level had left open.

## Setup

- Twilio free trial: email + SMS signup, the owner's iPhone added as a Verified Caller ID (trial inbound is accepted only
  from verified numbers; every trial call opens with Twilio's announcement; 10-minute cap).
- Secrets: `TWILIO_ACCOUNT_SID` and `TWILIO_AUTH_TOKEN` in `~/.ai-phone/secrets.env` (0600), exported into the CLI's
  environment for the one command that needs them. They never appear in the config, the journal or a log.
- Same daemon and config as the Telnyx spike (`~/.ai-phone/spike-telnyx.yaml`), so the Telnyx trunk, the Twilio trunk and
  a LAN `sip` line ran side by side on one daemon.

## `lines add twilio --key-env TWILIO_ACCOUNT_SID --secret-env TWILIO_AUTH_TOKEN --country US --id tw --yes` (23:34)

Nine carrier requests, one journal step each, 3.2 s wall clock:

| Step | Request | Result |
|---|---|---|
| search | `GET …/AvailablePhoneNumbers/US/Local.json`, `GET pricing…/PhoneNumbers/Countries/US` | 10 numbers at 0.87 GBP/month (the account's currency) |
| credential_list | `POST …/SIP/CredentialLists.json` | `CL…` |
| credential | `POST …/SIP/CredentialLists/CL…/Credentials.json` | SIP user `aitw…`, password generated by the CLI, stored only in `secrets.env` |
| domain | `POST …/SIP/Domains.json` (`SipRegistration: true`) | `ai-phone-tw-<6 hex>.sip.twilio.com` |
| domain_mapping | `POST …/SIP/Domains/SD…/Auth/Registrations/CredentialListMappings.json` | the credential list may register |
| number | `POST …/IncomingPhoneNumbers.json` with `VoiceUrl` = twimlets echo `<Dial><Sip>sip:user@domain</Sip></Dial>` | +1 555 555 0124 |
| trunk | `POST trunking…/Trunks` | `ai-phone-tw-<6 hex>.pstn.twilio.com` — **allowed on this trial account**, so the line came up with outbound; the provider's inbound-only fallback (commit e7c0245) was not needed here |
| trunk_credential_list | `POST trunking…/Trunks/TK…/CredentialLists` | outbound authenticates with the same credentials |

The written line: `kind: trunk`, `registrar: sip:<domain>.sip.twilio.com`, `outbound_proxy`/`dial_domain: <trunk>.pstn.twilio.com`,
`register_via_proxy: false` (REGISTER goes to the domain, INVITEs out go to the trunk), `transport: udp`,
`accept_invites_from: registered_trunk` with Twilio's eight signalling /30s as `trusted_cidrs`, `provider.resources` holding
the four SIDs `remove` needs. `lines list` shows `tw  trunk +15555550124 (twilio: ready)`.

## Registration and the inbound call

- After a daemon restart both trunks registered within seconds: Telnyx (TCP) and Twilio (UDP to the SIP domain), from
  behind the same home router, no port forwarding, no STUN.
- Inbound from the verified iPhone (23:42): the INVITE came from `54.172.60.3` (inside the pinned `54.172.60.0/30`, so
  `registered_trunk` admitted it — over UDP, which means Twilio's INVITE from an edge address different from the registrar's
  did get through this router's NAT), From `+44…@<domain>.sip.twilio.com`. Six turns with barge-in:

| Turn | Caller said | Reply | first_audible |
|---|---|---|---|
| 0 | "Hey, testing one, two, three. Can you hear me?" | "Yes, I can hear you clearly." | 1618 ms |
| 2 | "Yeah." | "Great, I'm ready to help." | 1314 ms |
| 3 | "Yeah, please read the alphabet slowly." | "A, B, C, D, …" | 1416 ms |
| 4 | "Okay, interruption, interruption, interruption." (barge-in) | cut off | — |
| 5 | "Okay, cool. Your interruption works. I'm gonna hang up. Bye now." | "Goodbye!" | 1479 ms |

Stage times: STT 94–433 ms, LLM first clause 585–674 ms; the host was still 12 GB into swap (see the Telnyx spike), which is
where the extra half-second over the LAN figures comes from.

## Outbound through the trunk (23:43)

`ai-phone call +44… --line tw`: `dialling sip:+44…@<trunk>.pstn.twilio.com` → 183 → 180 → answered after 18 s of ringing →
the opening line played → the callee said nothing → "Still there?" → hangup for silence after 21 s, exit 0. Caller ID was the
Twilio number. On a trial the destination must be a verified number; it was.

## What this settles for the gate

- `lines add` end to end against a real carrier API: done here (the Telnyx account's connection cap made it impossible there).
- A number bought by `lines add` registers from behind the home router: done; it stays in the 24-hour soak that restarted
  at 23:35 with both trunks, so the "stays registered 24 h" figure will cover it too.
- `lines remove tw` and "nothing left in the account" are run after the soak so the removal is exercised on a line that
  has been registered for a day; the result goes in this file.

## Notes for the docs

- Twilio prices come back in the account's currency (GBP here), not USD; the CLI prints what the carrier says.
- A trial account's number is reachable only from its verified caller IDs, and every call starts with Twilio's announcement;
  README should say so where it recommends the Twilio trial for a first test.
