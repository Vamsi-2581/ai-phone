# Latency rerun, 2026-10-26

The current default local pipeline measured **1074.3 ms p50 / 1719.1 ms p95**
from the caller's last voice-active chunk to the first non-silent frame handed
to PJSIP. All 20 calls produced a complete measured turn. The **p50 < 1000 ms
gate failed**, by 74.3 ms.

## Conditions

- Apple M5 Pro, 24 GiB RAM, macOS on Apple Silicon.
- Runtime source revision: `77cb926`.
- Local Qwen3.5 4B, Parakeet v2 and Kokoro `af_heart`, speed 1.0.
- Current default inbound greeting, phone instructions and conversation timings.
- The existing 20 recorded utterances, one per loopback SIP call, over 8 kHz PCMU.
- Each peer remained open for 18 seconds, followed by a one-second gap.
- Fresh isolated configuration, state and logs; no carrier registration or external brain.
- All model assets downloaded before startup; model loading and calls ran offline.
- No test suite or model download ran alongside the calls.

This was a measurement under the host's remaining background load. After model
warmup, about 20.3 GiB of swap was in use; after the calls, about 19.9 GiB. During
the call window the host recorded 408 MiB of swap-ins and 22 MiB of page-outs.
These are host-wide counters and do not identify which process paged. CPU idle
was about 88% in the boundary samples, not a continuous profile.

Each row has 20 samples. The report selects a sorted sample at
`round((percentile / 100) * (n - 1))`, retaining the existing gate convention.
Stage percentiles should not be added: they need not describe the same turn,
and prompt evaluation is part of time to the first LLM clause.

There were no incomplete turns or brain errors. Each call had a distinct ID,
one positive first-audible measurement matching its t0/t5 timestamps, and a
nonempty received recording. The final recorded cumulative ring counters were
34 transmit underruns and zero receive overruns. Both test process groups were
confirmed stopped after the run. No barge-in scenario was measured.

## Comparison with the historical result

M1's 2026-09-03 result remains **873.8 ms p50 / 1437.6 ms p95**, measured over
20 calls with roughly 10 GB of swap in use. The current run is about 201 ms
slower at p50 and 281 ms slower at p95. The later 2055 ms p50 observation on a
busy host was not reproduced in this run.

Several conditions differ. M1 cached its whole short system prompt; current
code caches the fixed phone instructions and evaluates the call-specific
instructions each turn. Memory wiring, scratch-cache clearing and idle
keep-warm inference were added after M1. The model repository names match, but
the historical model and voice snapshot bytes were not recorded here; current
Kokoro loads its voice from the model snapshot. Endpoint silence and ordinary
clause-size thresholds are unchanged.

The new result establishes current performance under the recorded conditions.
It does not isolate the cause of the difference. A quiet-host comparison with
fixed model snapshots and matching instructions remains necessary to do that.
