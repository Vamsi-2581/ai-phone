# Phonon integration, 2026-10-27

Twenty local calls completed with **1499.6 ms p50 / 1939.2 ms p95** first-audible
latency. The one-second median target was missed. Phonon's TTS stage measured
**51.9 ms p50 / 83.8 ms p95**. All five interruption scenarios cancelled and
resumed correctly; four met the 300 ms stop limit. These are separate results
from the earlier standalone speech benchmark.

Phonon 31M English runs directly through MLX in the daemon's TTS worker. The
setup wizard offers it alongside Kokoro and can download and preview its
bundled voice. Existing configurations keep Kokoro; new setup sessions suggest
Phonon. To select it manually:

```yaml
tts:
  engine: phonon
  voice: default
  speed: 1.0
```

Run `uv run ai-phone models pull`, then restart the daemon. Phonon supports one
bundled voice at normal speed in this integration. Kokoro retains its English
voice selection and adjustable speed.

## Implementation

The worker loads a pinned local snapshot, tokenizer and voice before accepting
calls. Generation uses 80 ms streaming chunks and temperature 0.3. Its 24 kHz
audio passes through the existing VHQ resampler into 16 kHz int16 / 20 ms frames;
leading silent frames and empty final chunks are discarded. Cancellation is
checked between native chunks and output frames, and cancelled generation IDs
remain rejected if later clauses arrive.

Streaming also exposed a buffering problem: a fast producer could fill the
output rings and drop later speech. The worker now waits for capacity while
remaining responsive to cancellation and shutdown. The pipeline preserves
frame order, rejects stale generations and waits for all queued audio before
completing a turn. Cached greetings and other phrases also respect ring
capacity, and startup caching drains frames as they arrive. None of this waits
inside the PJSIP callback.

## Measurement conditions

The local call runs use an Apple M5 Pro with 24 GiB RAM, the default local
Qwen3.5 4B brain and Parakeet v2, Phonon's bundled voice, and 8 kHz PCMU over
loopback SIP. Each run has fresh isolated configuration, state and logs, with
no carrier registration or external brain. Model loading and calls run
offline. Test suites and model downloads run separately from the calls.

The latency gate uses the same twenty recorded utterances and default phone
instructions as the [2026-10-26 Kokoro run](latency-2026-10-26.md). The first
attempt preserved the old caller behavior: playback EOF hangs up, even before
the nominal 18-second limit. Those files last only 12.675–14.875 seconds.
Eleven replies were cut off, leaving nine complete turns. There were no brain
errors, but this attempt is not a valid twenty-complete-call gate. Its raw
rows and received recordings are retained.

The complete-turn harness preserves every original PCM byte, appends digital
silence to make each input 45 seconds long, and hangs up the isolated call
0.75 seconds after the first complete turn before quitting the peer. Original
and padded file hashes are recorded. This changes the permitted reply duration
without changing the spoken input. An earlier padded-input attempt stopped
after one completed reply because quitting PJSUA with its WAV player and call
still active caused an assertion; its logs are retained separately.

First audible response is measured from the caller's last voice-active chunk
to the first non-silent frame handed to PJSIP, including endpoint wait. It
excludes downstream network and handset buffering. Percentiles select the
sorted sample at `round((percentile / 100) * (n - 1))`, matching the existing
gate. Stage percentiles should not be added.

The host remained under memory pressure. Between model-ready and post-call
snapshots, used swap rose from 22.5 to 22.9 GiB. Over that 348.8-second window,
host-wide counters recorded 5252.5 MiB of swap-ins and 5702.2 MiB of swap-outs.
Unused RAM was 286 MiB and 309 MiB at the boundaries. A pre-existing daemon
also remained running; it was untouched and never called by these tests.
These observations establish background load but do not attribute the latency
difference to a particular process or cause.

## Complete-call results

| Stage | p50 (ms) | p95 (ms) |
|---|---:|---:|
| Endpoint wait | 296.3 | 304.9 |
| STT | 472.4 | 715.9 |
| LLM prompt evaluation | 621.0 | 904.1 |
| LLM first clause | 701.6 | 995.0 |
| TTS first chunk | 51.9 | 83.8 |
| Egress | 11.1 | 18.2 |
| First audible response | **1499.6** | **1939.2** |

Each row contains all twenty calls. There were no incomplete turns or brain
errors. Each call had a distinct ID, matching positive t0/t5 timing, and a
valid nonempty received WAV. Original PCM prefixes and silent padded tails
were verified byte-for-byte. The latest selected cumulative ring counters
were 38 transmit underruns and zero receive overruns. Both owned process
groups were confirmed stopped and their SIP ports free afterward.

The **p50 < 1000 ms gate failed**, by 499.6 ms. Compared with the previous
Kokoro call run, the observed TTS-stage median is lower, while the STT and LLM
stages and overall median are higher. This is not a controlled model-only
comparison. Eighteen of twenty caller transcripts match the supplied text
references after normalization; the same two differences also appear in the
previous Kokoro run. The latency gate does not certify transcription accuracy.

## Interruption method

Five separate offline relay calls use a long `say`, interrupted by one of the
first five recorded caller sentences. The model still has unfinished TTS work
when the caller speaks. Each check requires audible output before interruption,
an `interrupted` result, the complete caller transcript, and successful
playback of a subsequent `say`.

A private observer records the actual transmit-ring flush inside the PJSIP
media callback and nonzero output-frame timestamps. It keeps these observations
in memory and writes them at shutdown. Acceptance requires a flush within
300 ms of the controller's first detected speech chunk, no output-ring
overflows, and at least 25 quiet callback frames between flush and the next
`say` request. This instrumented run is separate from the latency gate.

The observer does not carry generation tags at media egress. Silence evidence
therefore applies to that measured quiet interval. Nonzero output during the
fresh `say` confirms resumed playback; it does not independently attribute
each later frame to a generation. Tagged-frame unit tests separately cover
stale-generation rejection. The stop metric includes the consumer's flush,
whereas the ordinary turn record stops at the controller's request; neither
includes the phone's jitter buffer.

## Interruption results

All five long replies returned `interrupted`; all five complete caller
sentences were transcribed, ignoring case and punctuation; and all five fresh
replies completed with audible output. At each interruption, both output-ring
overrun counters were zero. The measured quiet intervals contained zero nonzero
output frames.

| Call | Actual stop (ms) | Observed quiet interval (s) |
|---|---:|---:|
| 1 | 396.1 | 2.49 |
| 2 | 235.8 | 3.15 |
| 3 | 257.7 | 3.72 |
| 4 | 237.2 | 2.49 |
| 5 | 239.8 | 3.22 |

Stop latency was **239.8 ms p50 / 396.1 ms p95**. Four calls met the 300 ms
limit; the first missed it, so the strict five-interruption gate **failed**.
On that call, 377.2 ms elapsed before the controller requested the flush; the
media callback then flushed 18.9 ms later. The detector requires sustained
speech above its playback threshold. These observations do not isolate why
the first detection interval was longer; no threshold was relaxed and no
replacement interruption run was selected.

The interruption harness raised a cleanup error after its observations had
been saved. Validation was recovered from those artifacts, and a separate
process/port check confirmed that no test processes remained. The original
error and recovered validation are both retained. The final latency run uses
the corrected cleanup sequence.

## Repository verification

- Full unit suite: **1004 passed** in 235.36 seconds.
- Full offline integration suite: **30 passed, 8 skipped, 2 deselected** in
  146.62 seconds. The skips are uncached optional models; the two paid
  subscription tests were excluded. Actual Phonon, Kokoro, Parakeet, the local
  4B brain and isolated SIP tests ran.
- All 71 measured production/dependency file hashes matched the final source.
  The setup tests cover engine selection, preserving existing settings,
  download selection, preview, and saved configuration.

```sh
env -u NO_COLOR timeout 900 uv run pytest tests/unit -q -p no:cacheprovider
env -u NO_COLOR HF_HUB_OFFLINE=1 HF_HUB_DISABLE_IMPLICIT_TOKEN=1 TRANSFORMERS_OFFLINE=1 \
  AI_PHONE_TEST_SIP_PORT=5080 timeout 1800 uv run pytest tests/integration -q -p no:cacheprovider \
  -k 'not a_claude_subscription and not a_chatgpt_subscription'
```

The repository tests passed; the measured call-latency and interruption timing
gates did not. No live carrier or paid subscription call was made.

Recordings, raw turn logs, source and input hashes, and host memory snapshots
are retained locally and are not distributed with the repository.
